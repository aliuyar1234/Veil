# Implementation Plan: Dictionary Detection

**Branch**: `008-dictionary-detection` | **Date**: 2025-12-15 | **Spec**: spec.md
**Input**: Feature specification from `/specs/008-dictionary-detection/spec.md`

## Summary

Implement dictionary-based PII detection for names, locations, and companies using locale-specific
dictionaries (AT/DE/CH). Uses FST for efficient storage, Jaro-Winkler for fuzzy matching, and
integrates with existing veil-detect pipeline.

## Technical Context

**Language/Version**: Rust (stable, 1.75+)
**Primary Dependencies**: fst, strsim, unicode-segmentation, unicode-normalization
**Storage**: In-memory FST with optional file-backed dictionaries
**Testing**: cargo test, TDD per constitution
**Target Platform**: Cross-platform library (same as veil-detect)
**Project Type**: Library crate (veil-detect extension)
**Performance Goals**: <1ms lookup per word, <100MB memory for all built-ins
**Constraints**: Word boundary enforcement, Unicode normalization
**Scale/Scope**: ~30K built-in entries, support for 1M+ custom entries

## Implementation Phases

### Phase 1: Core Types & Storage

1. Add dependencies to veil-detect Cargo.toml
2. Create dictionary module structure
3. Implement DictionaryEntry, DictionaryCategory, Locale
4. Implement Dictionary with FST storage
5. Implement exact lookup

### Phase 2: Fuzzy Matching

1. Implement FuzzyConfig and FuzzyMatch
2. Add Jaro-Winkler matching via strsim
3. Implement Dictionary::find_fuzzy()
4. Add configurable threshold

### Phase 3: Registry & Loading

1. Implement DictionaryRegistry
2. Implement file loading (line-delimited format)
3. Implement DictionaryLoadConfig
4. Add hot-reload support (optional)

### Phase 4: Detection Integration

1. Implement DictionaryDetector
2. Implement Detector trait
3. Add word boundary detection
4. Add confidence scoring
5. Wire into DetectorRegistry

### Phase 5: Built-in Dictionaries

1. Create curated dictionary files
2. Embed as compile-time resources
3. Implement lazy loading
4. Test with real DACH names/locations

### Phase 6: Polish

1. Documentation and examples
2. Performance benchmarking
3. Memory usage validation
4. CLI integration (optional flag)

## Risk Mitigation

| Risk | Mitigation |
|------|------------|
| Large dictionary memory | FST compression, lazy loading |
| Fuzzy matching performance | Limit candidate generation, cache results |
| False positives on common words | Word boundaries, context signals, configurable threshold |
| Dictionary licensing | Use only public statistics data |
